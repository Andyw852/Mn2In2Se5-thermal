# test/ — κ cross-check data package (MnIn₂Se₄ vs Mn₂In₂Se₅, phono3py vs ShengBTE)

Purpose: find the root cause of **the κ values from phono3py and ShengBTE differing by 6–10× for the same fc2/fc3**.

## The key question (to be resolved)

MnIn₂Se₄, same 6.45 Å cutoff, same force constants, **same 11×11×11 = 1331 q-points**:

| 300 K (W m⁻¹ K⁻¹) | ShengBTE | phono3py | ratio |
|---|---:|---:|---:|
| RTA | **0.35647** | **2.24981** | 6.3× |
| full solution (CONV / LBTE) | **0.40633** | **3.9054** | 9.6× |

Ruled out: q-mesh (the 6.3× difference remains on the same mesh), force-constant source (both `cutoff_scan/cut3_6p45`),
min_freq (both −3.1488e−05 THz), NAC (both off), isotope (both on).
phono3py σ broadening from 0.05 to 2.0 was tried and the result is completely unchanged (2.24981), which shows that σ has no effect on this path, so broadening cannot yet be ruled out.

## Directory structure

```
MnIn2Se4/
  fit/                            S1_fit fitting inputs and outputs (fit-fc-thermal)
    fit_config.json               pheasy fit configuration (RFE-OLS + ALASSO, RASR=BHH)
    fit_manifest.json             fit manifest (including code.optimizer.md5, geometry.ws_extended_pairs)
    phonon_summary.json           post-fit phonon stability determination (stable, min_freq)
    POSCAR / SPOSCAR              primitive cell / 4×4×1 supercell (112 atoms)
    dataset_disps.npy             training-set displacements (45 frames)
    dataset_forces.npy            training-set forces
    fc2.hdf5 / fc3.hdf5           force constants in phono3py format (input for the downstream κ)
  phono3py_disp.yaml              phono3py input (primitive cell + displacement information)
  shengbte_export/                ShengBTE-format export (converted from the fc2/fc3 above)
    FORCE_CONSTANTS_2ND/3RD
    POSCAR
  kappa_shengbte_20x20x5/         production setting: ShengBTE iterative solution @ 20×20×5 (2000 q-points)
  kappa_shengbte_11x11x11/        same-mesh control: ShengBTE iterative solution @ 11×11×11 (1331 q-points)
  kappa_phono3py_lbte_11x11x11/   direct phono3py solution @ 11×11×11 (1331 q-points)

Mn2In2Se5/
  fit/                            S5_fc fitting inputs and outputs (kl-dft-cpu)
    fit_config.json               pheasy configuration (ALASSO, RASR=BHH, 4×4×1, 144 atoms)
    fit_manifest.json
    phonon_summary.json           stable, min_freq −2.17e−07 THz
    POSCAR / SPOSCAR
    BORN                          dielectric/Born effective charges (NAC=off at this step; for checking only)
    dataset_disps.npy / dataset_forces.npy54 frames
    fc2.hdf5 / fc3.hdf5
  phono3py_disp.yaml
  shengbte_export/                ShengBTE format (used by step6)
  kappa_shengbte_16x16x4/         production result: ShengBTE iterative solution @ 16×16×4
```

Each kappa_* directory contains:
- `kappa_summary.json` (generated by the script; contains solver / bte_method / mesh / 300 K κ / stability determination)
- `BTE.KappaTensorVsT_RTA`, `BTE.KappaTensorVsT_CONV` (raw ShengBTE output, 16 temperatures)
- `BTE.omega` (phonon frequencies), `BTE.v` (group velocities), `BTE.qpoints` (q-point list)
- `CONTROL` (ShengBTE input), `FORCE_CONSTANTS_2ND/3RD` (the force constants actually used in that run)
- `shengbte.log`
- phono3py directories additionally contain `kappa-m111111.hdf5` (raw phono3py κ output) and `coleigs-m111111.hdf5`
